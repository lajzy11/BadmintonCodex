球友的困擾

為了能在想打球的時候找到零打資訊，某些球團也需要加入到他們的群組內才能報名，所以會加入很多不同的 FB 社團、粉專和 LINE 社群、群組等，資訊很不統一
→ 希望有報名零打的統一入口（也許還是要跟現有平台串接）
→ 有 LINE 帳號感覺不錯（網頁快速入口/查看自己的預約/推播提醒訂閱的球團資訊和預約）

LINE 社群、群組內大多是用接龍的方式進行報名，造成日常會接收到很多非必要的訊息、通知
→ 透過入口主動的尋找，而非被動的接受

若是用 FB 或 LINE 帳號報名，會有透漏個人資訊的風險（EX.有遇過女球友被私訊騷擾），而且如果突然有事需要取消，可能需要在群組內告知原因，但覺得這算是個人隱私
→ 公開零打名單、帳號的資安問題（除了團主可見，個人資訊盡量不公開、除了朋友可見，出席資訊盡量不公開）

群組內有重要訊息時，雖然團主會＠所有人，但因為日常訊息太多，大多數人都是關靜音，導致訊息容易被遺漏（EX.人數不足或場館臨時休館無法開團，都遇過有人白跑一趟）
→ 團務與報名訊息混在一起，同第一點

雖然報名時會報級數，打球過程中也可以再調整，但當遇到有人高報/低報時，都很容易打得不盡興，而且覺得跟同級數的年輕男生、女生、老人、小孩打起來落差很大
→ 即使有程式輔助，大多還是會有團主介入安排，需要給團主手動調整的空間
→ 思考是否需要加入其他成員參數

若團主排點時沒有特別留意，容易遇到跟同樣的人配到好幾場的情況
→ 系統排點應該把組對重複率設為參數
→ 主觀資訊：球友報名時自己選填，但團主可以事後修改（報名級數、性別、特殊資歷（校隊、體保））
→ 客觀資訊：給系統自動記錄，但團主可以編輯或備註（今天打過幾場、對戰紀錄、出席率、跟誰配對過）
→ 觀察資訊：團主主動填寫，個人備註（性格、要求）、與其他球友的關係、球風、偏好站位、身體況狀（體力、是否剛受傷復出）
→ 主要功能是由系統算出一組建議名單，也許要向我們可以選擇AI的回覆語氣一樣，也事前讓團主針對這個建議系統進行簡單的客製化
例如是否開放跨2級以上的人進行配對、偏好混雙或是男女雙方開等等

參加球團許久，但除了在場上的時間下場後不太會跟別人交流，所以交不太到朋友
→ 在球友端新增場邊小遊戲，需要是被排到點時能暫停或立刻結算的類型
→ 如果未來有開放球友PO文，感覺看球友的內容也很有趣，也可以增加聊天話題

有些球團會在場邊攝影，並放上全團社群、相簿，但有時候其實不想被拍攝又不好意思說出口
→ 報名時新增是否願意被拍攝的選項

遇到沒禮貌、沒球品的球友會很不開心，雖然知道可以去請團主排開，但又怕給帶來麻煩
→ 在球友端新增減少同組/場的選項或黑名單機制

打羽球受傷的機率不低，但對怎麼處理不太清楚
→ 在球友端新增羽球小知識庫，小短句（EX. 你知道...）

對於搶球造成的斷拍處理沒有統一的解法，容易造成紛爭
→ ?

站在「球友」的角度會希望在系統上「看到」什麼、或「能做」什麼
→ 顯示自己的對戰紀錄，以及下一場的配對，和等待組數
→ 會想偷看隊友的資訊，配合的好會想要給予鼓勵，配合不好會想要減少配對





團主的困擾

若球團群組內報名人數不足，需要轉PO到各處羽球零打社團徵人
→ 希望有報名零打的統一入口，區分球團內報名時間，公開刊登時間

雖然有制定截止時間與處罰條件，但球友還是會因為各種理由缺席，對於零打的球友也很難實行罰則
→ 可限定有帳號者報名或開放零打，註冊時需綁定手機/帳戶
→ 可限定有到場率%數報名或開放零打，系統記錄到場率供團主觀看

對於非固定租場的團主，可能每次開團前都需要再次跟場地方確認當天狀況
→ 大後期再來處理場地端問題

球團付款方式主要分為：現金、轉帳、Line Pay，報到時常常感覺到團主有些手忙腳亂，要邊記帳邊安排上場順序，造成報到排隊人潮
→ 分流 Line Pay 人士，讓對方開團前付款或現場掃碼付款(像餐廳)，團主專心負責現金和轉帳即可
→ 系統需在開場前，記錄該成員的零打方案（應付款金額、打球時間）、付款方式、級數、綁定人員

會有明明球況不差卻頻繁要求換球的人，造成成本上升
→ ?

對於有級數限制的團，若報名者不符合級數，團主現場處理會很為難
→ 針對級數限制給予說明欄位

排點時會有AB想要綁定、AB想要對打等等客製化要求需要記得
→ 需要有互相綁定、綁一場、打一場、減少同組的選項（長按成員觸發功能鍵）

因為要負責排點，團主本人有時難以自己下來打球
→ 系統排點功能：自動輪播、級數、等待時間、已打場數、男/女/混雙

排點時需要隨時關注每場的狀況，EX.人是否到齊、是否已結束有空場
→ 團主一鍵結束，場地再次廣播，由球友端回報空場、缺人(?)

由於球場較吵雜且有人會去廁所、抽菸，團主需要重複喊人、找人
→ 球友端需要呈現已輪到自己，目前不方便先找下一位，擔心被濫用來躲不喜歡的人、人員隨時可能變動，不顯示下一組組合

因為排點需求，有些團主會詢問每場對戰的輸贏或比分
→ 支援由球友端自行回報比分，團主不將此設為主要流程

需要解決球員間的各式紛爭
→ 球友端呈現自己的對戰紀錄、已打場次、已等待時間（思考是否更容易造成爭議）

每次開團的羽球用量不同，需要定期去補貨羽球
→ 換球紀錄(?)針對羽球用量提供簡單的數據或推測

大多團主可能習慣磁鐵、卡牌的排點模式
→ 心目中希望可以有像 inline POS機辦理預約報到時，可以直接把該組客人拖曳到某個桌號那樣的UI機制
