# 羽球零打平台｜團主訪談整理（初版）

> 資料來源：團主深度訪談（開團當天 + 開團當下工作流程）
> 訪談對象：現任團主，負責報名/帳務；共同經營者負責排點/場地/採購
> 整理目的：作為產品定義與功能規劃的輸入依據

---

## 一、角色與情境設定

| 項目 | 內容 |
|---|---|
| 團隊規模 | 中小型球團，單場約 8 人/面場，依候補人數彈性加開場地 |
| 團主分工 | 團主 A（受訪者）：報名確認、帳務、報到；團主 B：排點、場地/廠商關係、採購 |
| 共同管理 | 球團規則、爭議處理、活動規劃 |
| 使用場景時間軸 | 15:00 前（報名確認）→ 15:00-20:00（場地調度）→ 20:00 前（名單整理）→ 20:50（報到尖峰）→ 開賽中（排點+觀察）→ 結束（收尾/對帳） |

---

## 二、痛點分析（依流程階段）

### 階段 1：賽前調度（15:00–20:00）
| 痛點 | 描述 | 嚴重度 |
|---|---|---|
| 人數不確定性 | 15:00 人數不如預期需跨平台徵人 | 中 |
| 場地彈性調度 | 依候補人數（每滿 8 人+1 場）動態決定開幾面場，需與場館即時確認 | 中 |
| 名單雙軌記錄 | 需手寫筆記本 + 匯入排點系統，資料重複輸入 | 高（效率） |

### 階段 2：報到收費（20:50 起，尖峰期）
| 痛點 | 描述 | 嚴重度 |
|---|---|---|
| 紙本核對耗時 | 人潮尖峰時需在筆記本逐一找名字核對 | 高 |
| 多元付款方式並存 | 現金/轉帳/LinePay 同時存在，需個別確認收款畫面或找零 | 高 |
| 出錯率高 | 曾發生算錯錢、漏勾報到紀錄 | 高 |
| 空間轉移干擾 | 報到同時要從休息區移動到場地內，流程中斷、需插隊處理 | 中 |
| 人力吃緊 | 尖峰時段團主 A 同時處理報到+移動指揮，是全場最忙碌時段 | 高 |

### 階段 3：排點（開賽中，全程）
| 痛點 | 描述 | 嚴重度 |
|---|---|---|
| 級數認知落差 | 系統自動排點依級數，但團主對成員實際程度的認知常與系統標籤不同，需手動調整 | 高 |
| 人際偏好處理 | 需手動安排朋友/情侶同場、迴避「不想同場」的成員組合 | 高（隱性） |
| 公平性爭議來源 | 排點是成員最容易不滿、甚至默默退出的環節；等待時間、上場次數是否公平為核心爭議點 | 高（信任面） |
| 持續觀察負擔 | 非全程緊盯，但需持續留意場上狀態（進步、受傷、情緒），無法真正放鬆 | 中 |
| 團主自身難以上場 | 需等狀況穩定才能排自己上場，人力不足時需請熟識球友代為廣播 | 低 |

### 階段 4：突發狀況（全程）
| 痛點 | 描述 | 嚴重度 |
|---|---|---|
| 人身安全事件 | 受傷、身體不適頻繁發生（尤其冬季），需自備/借用藥品 | 中 |
| 場地/設備異常 | 場地漏水、冷氣故障、音響被借走等不可控狀況，需臨場應變（換場、取消、口頭喊聲） | 中 |
| 中途離場 | 抽菸/公務電話等原因暫離找不到人；受傷者需先讓下一組上場 | 中 |
| 未到未候補的收費灰色地帶 | 非團內成員爽約，收費與否、能否收到都不確定；團內成員則靠群組道德壓力收費 | 中 |
| 插花現場報名 | 無報名者臨場想加入，需臨場評估程度是否可收 | 低 |

### 階段 5：收尾
| 痛點 | 描述 | 嚴重度 |
|---|---|---|
| 器材/場地收拾協調 | 需叫大家下場、收球/音響/桌子、確認遺留物品 | 低 |
| 雙團主對帳 | 結束後需與共同經營者對帳、盤點球的用量與庫存 | 中 |
| 下週報名銜接 | 現場需即時開放下週報名意願收集 | 低 |

## 三、使用者故事（User Stories）

### 報到收費相關
- **US-01**：身為團主，我希望能透過單一系統同時完成「身份核對」與「收款確認（含 LinePay/轉帳/現金）」，這樣我就不用在紙本和系統間來回切換，降低尖峰時段算錯錢、漏勾人的機率。
- **US-02**：身為團主，我希望報到時能快速搜尋/掃描（如 QR code）找到報名者，這樣即使人潮眾多也能維持效率。
- **US-03**：身為團主，我希望系統能自動記錄每筆收款方式與金額，這樣事後對帳時不需要重新謄寫筆記本內容。

### 排點相關
- **US-04**：身為團主，我希望能在系統自動排點的基礎上，快速微調成員的實際級數標籤（非官方級數），這樣可以反映我對成員真實程度的了解。
- **US-05**：身為團主，我希望系統能讓我標記「避免同場」與「優先同場」的成員關係（不只是綁定隊友），這樣能減少人際衝突且不需每次手動記憶。
- **US-06**：身為團主，我希望系統能公開透明地顯示每位成員的等待時間/上場次數，這樣成員能自行理解排點邏輯，減少對團主主觀判斷的不滿與爭議。
- **US-07**：身為團主，我希望能即時看到場上是否有異常訊號（如同一人連續多場被排開、等待時間過長），這樣我能主動介入而非事後才發現成員不滿。

### 突發狀況相關
- **US-08**：身為團主，我希望能快速標記成員狀態（暫離、受傷、臨時下場），這樣排點系統不會誤將該成員排入下一場。
- **US-09**：身為團主，我希望系統能記錄「未到帳務」的處理狀態（已收費/待收費/不予追究），這樣可以避免帳務不清或重複追討。

### 賽前調度相關
- **US-10**：身為團主，我希望候補名單能與場地開場數邏輯連動（如每滿 8 人自動提示可加開場地），這樣我不需要手動計算候補人數對應場地數。
- **US-11**：身為團主，我希望報名系統與排點系統的名單能自動同步，這樣不需要手動謄寫或匯入，減少重複工作與出錯。

### 收尾/多團主協作相關
- **US-12**：身為團主，我希望能與共同經營的另一位團主共用同一份帳務與庫存紀錄，這樣結束後對帳不需要口頭核對或重新統計。

## 四、功能盤點（初步分類）

### 🔴 高優先（直接對應「最耗心力」痛點：報到收費、排點）
| 功能 | 對應使用者故事 | 說明 |
|---|---|---|
| 整合式報到＋收款介面 | US-01, US-02, US-03 | 搜尋/掃碼報到，單一畫面完成身份確認與收款登記，取代雙軌紙本記錄 |
| 多元支付狀態登記 | US-01, US-03 | 現金/轉帳/LinePay 皆可勾選登記，自動加總金額 |
| 手動微調排點＋級數標籤 | US-04 | 在自動排點基礎上，團主可快速覆寫/微調 |
| 成員關係標記（避免/優先同場） | US-05 | 除隊友綁定外，增加「迴避名單」功能 |
| 排點公平性儀表板 | US-06, US-07 | 顯示等待時間、上場次數，供團主與成員雙方參考 |

### 🟡 中優先（提升賽前與突發狀況效率）
| 功能 | 對應使用者故事 | 說明 |
|---|---|---|
| 候補與場地連動計算 | US-10 | 依候補人數自動提示可加開場數 |
| 名單自動同步 | US-11 | 報名系統與排點系統打通，不需手動匯入 |
| 成員狀態即時標記 | US-08 | 暫離/受傷/下場狀態，避免誤排點 |
| 未到帳務追蹤 | US-09 | 記錄未到者收費狀態，避免灰色地帶模糊 |

### 🟢 低優先（多團主協作與收尾）
| 功能 | 對應使用者故事 | 說明 |
|---|---|---|
| 多團主共用帳務/庫存紀錄 | US-12 | 結束後免口頭對帳 |
| 下週報名開放快速入口 | - | 現場結束時一鍵開放下週報名 |

## 五、待釐清/後續訪談方向（風格差異類，非共同流程）

以下屬於「各球團風格差異」，可視需要另外訪談其他團主以確認共通性：
- 分級標準的制定方式（是否有官方級數 vs 團內自訂級數）
- 未到扣款政策的嚴格程度（是否所有團都採道德勸說式收費）
- 是否辦理額外活動（聚餐、比賽）、辦理頻率
- 器材/場地成本分攤方式
