|文件欄位|內容說明|
|-|-|
|**產品名稱**|羽球排點系統 (Badminton Match Master)|
|**文件版本**|V1.0 (MVP Stage)|
|**目標對象 (TA)**|羽球臨打團團主、球隊管理者|
|**核心效益**|解決現場人力排點耗時、級數不均、場次分配不公及複雜人際綁定問題|

## 1\. 產品概述與核心目標 (Product Overview \& Goals)

### 1.1 痛點 (Pain Points)

* **認知負荷過高**：團主需同時記憶球員級數、男女混雙偏好、誰不想跟誰打（迴避）、誰要搭檔（綁定）。
* **公平性爭議**：手動排點易導致特定球員等待時間過長、打場數不均或級數落差過大（壓勝/慘敗）。
* **現場微調繁瑣**：現場突發狀況（如臨時請假、打一場要走、指定場地限制）難以快速彈性調整。

### 1.2 產品目標 (Core Objectives)

* **自動化**：一鍵演算法排點，3 秒內算出最佳配對組合。
* **高直覺性**：採用 POS 機卡牌化拖曳介面，降低操作門檻。
* **彈性客製化**：支援現場長按設定（綁定/迴避/休場）與場地規則限制。
* **智慧輔助**：提供現場自動叫號語音廣播與明亮/暗黑模式切換，適應各球館光線環境。
* **全平台適應 (RWD)**：跨平臺支援手機、平板與桌上型電腦，確保團主在手持行動裝置上也能輕鬆點擊與拖曳操作。

## 2\. 功能規格與需求 (Functional Requirements)

### 2.1 名單登錄與管理 (Player Management)

* **手動新增/編輯**：輸入姓名、性別（男/女）、級數 (Level 1\~10)。
* **批次匯入**：支援 CSV / 格式化文字（如 `張三,M,5`）快速載入報名名單。
* **動態狀態調控**：

  * **在場 (Active)**：納入自動排點計算。
  * **休息 (Rest)**：暫不排點（如離場、受傷）。
  * **累積數據**：即時紀錄已打場數、當前等待時間（輪空場次）。

### 2.2 智慧自動排點引擎 (Matchmaking Engine)

排點演算法基於 **加權評分機制 (Weighted Scoring System)**，在點擊「智慧自動排點」時，系統會計算所有可能組合之權重評分，選出總分最高（最優）的安排：

$$\\text{Score} = W\_1(\\text{Waiting}) + W\_2(\\text{Fairness}) + W\_3(\\text{LevelMatch}) - W\_4(\\text{Repeated}) + \\text{BoundBonus} - \\text{AvoidPenalty}$$

* **權重權衡機制**：

  1. **等待時間 (Waiting)**：優先安排連續輪空場次最長者上場（最高權重）。
  2. **場數公平 (Fairness)**：優先安排總打場數較少者上場。
  3. **級數落差 (Level Match)**：盡量讓對戰兩組之平均級數差最小（$\\le 1.5$ 級）。
  4. **重複率限制 (Repeated)**：扣除近 2 場內重複對戰或重複組隊之組合權重。
  5. **關係綁定 (Binding/Avoidance)**：強烈加分/扣分以落實指定規則。

### 2.3 POS 卡牌拖曳與現場介面 (POS-style Drag \& Drop UI)

* **卡牌化呈現**：每位球員顯示卡牌，包含：姓名、性別標示、級數、已打場數、當前狀態。
* **自由拖曳 (Drag and Drop)**：

  * 可直接將卡牌從「等待區」拖至「球場位置（隊伍 A / 隊伍 B）」。
  * 可在不同球場間互相調換球員。
  * 拖離球場即清空該位置並回歸等待區。

### 2.4 長按現場快捷選單 (Long-Press Quick Actions)

在球員卡牌上\*\*長按 500ms（或滑鼠右鍵）\*\*彈出快捷設定選單：

|選單功能|邏輯與運作方式|
|-|-|
|**互相綁定 (Bind Together)**|選取目標球員，此二人排點時必定在同一隊。|
|**僅綁一場 (Bind 1 Match)**|下一場強制安排同隊，完成後自動解除綁定。|
|***對戰一場 (Play 1)***|*下一場強制安排同場不同隊，完成後自動解除綁定。*|
|**迴避名單 (Avoid Match)**|選取目標球員，此二人排點時**絕不同場**（無論同隊或對手）。|
|**減少同組 (Reduce Teammate)**|降低兩人被分在同隊的機率（可用於調和打法相同者）。|

### 2.5 場地智慧控場與限制 (Court Management \& Rules)

* **場地自動推薦**：系統根據當前「在場總人數」動態提示場地數建議：

  * 人數 $< 6$ 人：建議 1 面場地。
  * 人數每增加 $6 \\sim 8$ 人：系統自動提示「建議加開 1 面場地」。
* **場地屬性設定**：可點擊球場標題設定規則：

  * **級數限制**：例如「高階場 (Level 7+)」、「友善場 (Level 1\~4)」。
  * **雙打型態偏好**：例如「男雙場」、「女雙場」、「混雙場」、「不限」。

### 2.6 語音廣播與視覺主題 (TTS Voice \& Theme Switching)

* **Web Speech TTS 廣播**：

  * 提供「場地備戰叫號」按鈕。
  * 觸發時自動進行語音朗讀兩次，範例：「第一場地，張三、李四、王五、趙六，請上場。第一場地，張三、李四、王五、趙六，請上場。」。
* **主題切換 (Theme Toggle)**：

  * **明亮模式 (Light Mode)**：適合日間或光線充足之羽球館。
  * **暗黑模式 (Dark Mode)**：低光源環境省電且視覺不刺眼。

## 3\. 響應式網頁設計與跨裝置限制 (RWD Requirements \& Constraints)

為了確保團主不論持平板（POS 模式）、智慧型手機或桌上型電腦皆能順暢操作，系統需針對不同螢幕尺寸進行響應式佈局調整與觸控優化：

### 3.1 螢幕斷點 (Breakpoints) 規範

* **Desktop / Large Tablet (≥ 1024px)**：

  * **佈局**：採標準「三欄式」或「雙欄側邊欄」佈局。
  * **顯示**：球場看板與等待區名單並排呈現，所有功能選單與控制面板預設展開。
* **Tablet / Small Screen (768px - 1023px)**：

  * **佈局**：改採「上下分層」或「彈性摺疊雙欄」。
  * **顯示**：球場看板佔據上方主要區域（水平滾動或網格縮放），等待名單摺疊至下方或側邊 Drawer。
* **Mobile (＜ 768px)**：

  * **佈局**：單欄流體佈局 (Single Column Flow)。
  * **顯示**：頂部固定核心控制列（智慧排點、語音叫號）；球場與等待名單透過 Tab 分頁（例如：「現行球場 (Court)」、「等待大廳 (Waiting List)」）進行切換，防止頁面過長。

### 3.2 觸控與互動限制 (Touch \& Interaction Constraints)

1. **最小觸控目標面積 (Minimum Touch Target)**：

   * 所有可點擊的卡牌、按鈕及控制項，觸控區域必須 $\\ge 44 \\times 44\\text{px}$，避免球場現場誤觸。
2. **觸控拖曳 (Touch Drag \& Drop) 與長按相容性**：

   * 行動裝置上需支援 HTML5 Drag \& Drop 與 Touch Events (TouchStart, TouchMove, TouchEnd) 轉化。
   * **防止衝突**：行動裝置長按 (Long-press $500\\text{ms}$) 觸發快捷選單時，需暫停原生頁面滾動 (Prevent Default Scrolling) 及 Context Menu，並給予震動 (Haptic Feedback) 或視覺高亮反饋。
3. **卡牌佈局動態適應**：

   * 球員卡牌在 Mobile 版型需精簡顯示（僅留姓名、級數 Badge 與狀態標示），避免擠壓卡牌內容。
4. **固定控制列 (Sticky Bottom Bar / Header)**：

   * 手機版「智慧排點」、「叫號廣播」等高頻率操作按鈕需懸浮固定於螢幕底部或頂部，隨手可及。

## 4\. 使用者流程 (User Journey Flow)

```
\[團主登入/開啟系統] 
       │
       ▼
\[批次/手動匯入報名名單] ──► \[設定場地數量與特別限制 (如高階場)]
       │
       ▼
\[點擊「智慧自動排點」]
       │
       ├─► 演算法計算：等待時間 > 場數公平 > 級數差 > 綁定/迴避
       │
       ▼
\[卡牌自動填入各球場 (隊伍 A / B)]
       │
       ├─► (可選) 團主進行 POS 拖曳微調或長按設定綁定
       │
       ▼
\[點擊「語音廣播」廣播入場] ──► \[比賽結束，點擊「結算此場」]
       │                                  │
       └──────────────────────────────────┘ (累積場數，更新等待時間，進入下一輪)
```

## 5\. UI / UX 介面佈局設計 (Interface Architecture)

整體介面採用 **動態自適應佈局 (Adaptive Layout)**：

* **頂部導覽列 (Header Bar)**：

  * 系統標題、明亮/暗黑模式切換開關、語音廣播控制按鈕、場地數量增減鍵。
* **控制面板區 (Control Panel)**：

  * 名單匯入區、智慧排點主按鈕、設定選單（跨級上限、排點偏好）。
* **中央球場看板區 (Court Dashboard)**：

  * 卡牌式球場列表（一號場、二號場...），顯示當前比賽人員，支援直接拖曳與長按觸發選單。
* **等待名單區 (Waiting Pool)**：

  * 顯示目前未上場人員卡牌，依「等待場次」排序，視覺化標示級數與性別。在 Mobile 端以分頁/Drawer 呈現。

## 6\. 非功能性需求 (Non-Functional Requirements)

1. **效能要求 (Performance)**：自動排點引擎運算時間必須控制在 **1 秒之內**（在 50 人、6 面場地規模下）。
2. **相容性與 RWD (Compatibility \& Responsiveness)**：支援 Phone / Tablet / Desktop Chrome, Safari, Edge 瀏覽器，完整適應各式螢幕尺寸。
3. **離線運作 (Offline Availability)**：系統應具備 LocalStorage 暫存機制，防止現場網路不佳導致名單與排點紀錄遺失。
4. **易用性與觸控體驗 (Usability)**：卡牌拖曳反應時間需 $< 100\\text{ms}$，並具備明確的 Touch Visual / Haptic Feedback。
