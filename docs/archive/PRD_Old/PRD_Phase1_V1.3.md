## 0. 版本異動說明 (V1.2 → V1.3)

V1.2 是較早的規劃版本；V1.3 依照目前實際完成並測試過的程式碼校正，主要有兩處方向性調整，以及多項細節修正／新增：

| 項目 | V1.2 | V1.3（本版，依實作現況） |
| :--- | :--- | :--- |
| 語音自動廣播 | 拿掉自動觸發，改團主手動按「叫號」 | **恢復自動觸發**。原本擔心的「多場搶播重疊」問題根因其實是廣播函式每次呼叫都執行 `speechSynthesis.cancel()`，會打斷佇列中其他廣播；移除這個多餘的 cancel 後，瀏覽器原生佇列機制即可讓多筆廣播依序播放不互相打斷。根因排除後，自動模式開啟時，場地自動補位＝同步自動叫號，團主仍可手動點擊「叫號」重播 |
| 場地自訂名稱 | 移除，固定用「1 號場」「2 號場」預設命名 | **恢復**。場地卡片標題旁提供編輯按鈕，可隨時重新命名，不影響其餘邏輯 |
| 場地數量設定方式 | 開團時設定總數（隱含下拉選單／輸入總數的介面） | 改為**逐一新增／刪除**：標題列「+ 新增場地」按鈕新增一個場地；每張場地卡片右上角提供「刪除」（比賽進行中禁止刪除，且至少保留 1 個場地）。此改法同時避開了「調整總數觸發整批重建、可能誤刪進行中比賽」的風險，不需要額外的保護邏輯 |
| $W_4$（重複扣分） | 規格中列為既有權重項目 | 補充實作細節：**直接複用既有的對戰歷史紀錄 (Match History Log) 計算**，不另外新增追蹤重複配對的資料欄位——只要候選 4 人組合曾經完整出現在歷史紀錄中（不論當時隊伍怎麼分），即視為重複並扣分 |
| 「重算預排」的行為 | 未特別定義 | 補充定義：排點引擎為決定性函式，狀態不變時重算會得到相同最佳解，屬正常行為；**當有多組候選並列最高分時，重算會在並列組合中隨機重新挑選**，並提供輕量視覺回饋（按鈕短暫顯示「已重新計算」） |
| 球友名單卡片 — 狀態控制 | 以 Checkbox 表示是否報到 | 改為**報到／休息／未到三顆按鈕**，取代單一 Checkbox；比賽進行中時鎖定，需先結算該場才能變更 |
| 球友名單卡片 — 狀態呈現位置 | 未特別定義 | 狀態徽章（在場等待／上場中／休息／未報到）移至姓名與級數同一列，與操作按鈕（報到／休息／未到）分開，前者是「顯示」，後者是「操作」 |
| 版面配置 | 未特別定義（隱含左：球場狀態＋預排區；右：球友名單） | 改為：**左欄僅放球場狀態**；右欄上方為預排空間、下方為球友名單（含功能列、篩選頁籤、名單，合併為單一卡片，不再拆成兩張） |
| 名單匯入解析健壯性 | 支援「姓名/級數」省略性別欄位 | 補充：解析前先剝除接龍常見的行首編號（如 `1.`、`2、`），並同時支援全形符號（／，．等），避免中文輸入法自動轉換全形導致整行解析失敗 |
| 資料一致性（關係綁定／刪除） | 未特別定義 | 補充規則：刪除球員或清除綁定時，需同步清除「其他球員」身上指向該球員的殘留關係（避免單向殘影持續影響評分）；比賽進行中禁止刪除該球員 |

## 1. 產品概述與核心目標 (Product Overview & Goals)

### 1.1 痛點 (Pain Points)
* **認知負荷過高**：團主需同時記憶球員級數、男女混雙偏好、誰不想跟誰打（迴避）、誰要搭檔（綁定）。
* **公平性爭議**：手動排點易導致特定球員等待時間過長、打場數不均或級數落差過大（壓勝/慘敗）。
* **現場微調繁瑣**：現場突發狀況（如臨時請假、指定場地限制）難以快速彈性調整；且缺乏「下一場預排」緩衝區，導致開場前手忙腳亂。
* **比賽歷史無軌跡**：現場缺乏時間紀錄與勝負比分登記機制，無法進行隊伍歷程回顧。

### 1.2 產品目標 (Core Objectives)
* **智慧與自動化**：一鍵演算法排點，並支援「自動模式 (Auto-Play Mode)」，當場地結束時自動將預排人員排上場，**並同步自動觸發叫號廣播**（團主亦可隨時手動叫號重播）。
* **預排緩衝區 (Preview Zone)**：提供「預排空間」，讓團主能預覽並提前手動微調下一組上場人員，或一鍵強制上場；「重算預排」在候選並列最高分時可重新抽選，並給予明確操作回饋。
* **高直覺性介面**：球場狀態、預排空間、球友名單分區清楚，球友卡片以簡短資訊＋直覺按鈕呈現。
* **個人化廣播**：支援語音重複次數 (1~3次) 與語音速度微調，適應高噪音球館；自動模式與手動叫號共用同一套不互相打斷的佇列機制。
* **賽程與對戰紀錄 (Match History)**：精確紀錄每場比賽開賽/結束時間、對戰陣容，並可選填勝負與比分；歷史紀錄同時作為 $W_4$ 重複扣分的判斷依據。

## 2. 功能規格與需求 (Functional Requirements)

### 2.1 名單登錄與管理 (Player Management)
* **手動新增/編輯**：輸入姓名、性別（男/女）、級數 (Level 1~10)。
* **批次匯入**：支援 CSV / 格式化文字（如 `張三/M/5`）快速載入報名名單。若使用者僅填寫「姓名/級數」（省略性別欄位），系統也需能正確解析。
  * 解析前先剝除常見的接龍行首編號格式（`1.`、`2、`、`3)` 等），避免編號被誤判為姓名的一部分。
  * 切分欄位同時支援全形符號（／，．等）與半形符號，因中文輸入法（尤其手機）容易自動轉換為全形。
* **報到機制 (Check-in)**：僅「已報到」者會被納入排點計算。未報到者停留在名單中但不參與排點。
* **狀態操作**：球友卡片提供「報到／休息／未到」三顆按鈕（取代 Checkbox），互斥切換：
  * **報到**：`checkedIn = true`，狀態為在場等待
  * **休息**：`checkedIn = true`，但暫不排點（如中途離場、受傷）
  * **未到**：`checkedIn = false`
  * 比賽進行中（狀態為上場中）時，三顆按鈕鎖定，需先結算該場比賽才能變更，避免留下無法正確歸位的殭屍資料。
* **批次操作**：提供「全體報到」「全體休息」快捷按鈕。
* **卡片呈現**：姓名、級數與狀態徽章（在場等待／上場中／休息／未報到）同列呈現；已打場數、輪空場次另列顯示；有關係綁定者顯示提示圖示。
* **刪除球員**：比賽進行中的球員禁止刪除；刪除時同步清除其他球員身上指向此人的殘留綁定/迴避關係，避免單向殘影持續影響排點評分。
* **累積數據**：即時紀錄已打場數、當前等待時間（輪空場次）。

### 2.2 預排空間與自動模式 (Preview Zone & Auto Mode)

#### 2.2.1 預排空間 (Preview / Up-Next Zone)
* **預覽陣容**：系統自動排點引擎會將算出的「下一組建議上場 4 人」暫存於「預排區（Up-Next Buffer）」。
* **重算預排**：點擊後重新執行排點計算。引擎本身是決定性函式，狀態未變時會得到相同最佳解——這是正常行為，非故障；當有多組候選並列最高分時，系統會在這些並列組合中隨機重新挑選，並在按鈕上短暫顯示「已重新計算」提供操作回饋。
* **一鍵上場 (One-Click Deploy)**：點擊「一鍵上場」按鈕，立刻將預排區成員推送至對應的空閒球場。

#### 2.2.2 開關「自動模式」 (Auto Mode Toggle)
* **開啟狀態**：任一球場結算且有空場時，系統自動將預排區人員安排上場，**並自動觸發語音廣播叫號**，隨後自動計算並補滿下一組預排陣容。團主仍可隨時手動點擊「叫號」重播。
* **關閉狀態**：比賽結束後，場地釋放為空閒狀態，等待團主手動點擊上場（此時廣播需手動觸發）。

### 2.3 智慧自動排點引擎與關係綁定 (Matchmaking Engine)
排點演算法基於**加權評分機制 (Weighted Scoring System)**：

$$\text{Score} = W_1(\text{Waiting}) + W_2(\text{Fairness}) + W_3(\text{LevelMatch}) - W_4(\text{Repeated}) + \text{BoundBonus} - \text{AvoidPenalty}$$

* $W_1$ 等待時間：等越久，優先權越高
* $W_2$ 公平性：已打場數越少，優先權越高
* $W_3$ 級數配對：級數落差越小，分數越高
* $W_4$ 重複扣分：**直接複用對戰歷史紀錄計算**——候選 4 人組合若曾完整出現在歷史紀錄中（不論當時隊伍怎麼分），依重複次數扣分，不另外新增追蹤欄位
* BoundBonus／AvoidPenalty：依長按快捷設定加減分

#### 排點規則客製化設定 (Matching Rule Settings)
* **權重項目開關**：$W_1$、$W_2$、$W_3$、$W_4$ 各自提供獨立開關，關閉的項目權重視為 0。
* **場次型態偏好**：可設定本場優先安排「男女雙」或「混雙」。

#### 現場長按快捷選單 (Long-Press Quick Actions)
在球員卡牌上長按 500ms（或滑鼠右鍵）彈出快捷設定選單：

| 選單功能 | 邏輯與運作方式 |
| :--- | :--- |
| **互相綁定 (Bind Together)** | 選取目標球員，此二人排點時必定在同一場（優先組隊）。持續生效，需主動解除。 |
| **僅綁一場 (Bind 1 Match)** | 下一場強制安排同隊，完成後自動解除。重新指定時，系統會同步清除舊搭檔身上殘留的反向連結。 |
| **對戰一場 (Oppose 1 Match)** | 下一場強制安排同場且分屬不同隊，完成後自動解除。同上，重新指定會清除舊對象的殘留連結。 |
| **迴避名單 (Avoid Match)** | 選取目標球員，此二人排點時絕不同場。 |
| **清除綁定** | 清除該球員自身的所有關係設定，並同步清除其他球員身上指向此人的殘留關係。 |

> **已知設計限制**：若綁定對象當下不在候選池中（例如搭檔還在別場比賽或尚未報到），系統會對每個不含目標的候選組合套用懲罰，可能造成當事人長時間排不進場。目前為刻意行為（模擬「盡量幫忙等搭檔」），尚無超時保護機制，未來可視情況加入「等候超過 N 輪即放棄湊搭檔」的保險機制。

### 2.4 場地管理 (Court Management)
* **新增場地**：標題列「+ 新增場地」按鈕，逐一新增，新場地預設命名「N 號場」。
* **刪除場地**：每張場地卡片右上角提供刪除按鈕；比賽進行中禁止刪除；系統至少保留 1 個場地。
* **場地自訂名稱**：場地卡片標題旁提供編輯按鈕，可隨時重新命名，不限制格式。

### 2.5 全螢幕模式與叫號廣播設定 (Full Screen & Broadcast Settings)

#### 2.5.1 全螢幕模式 (Full Screen Mode)
* 頂部按鈕支援一鍵切換 Browser Fullscreen（Web Fullscreen API），效果等同瀏覽器 F11，不另外設計專屬大螢幕版面。

#### 2.5.2 廣播設定面板 (TTS Speech Settings)
語音引擎（Web Speech Synthesis API）支援以下參數調整：
1. **重複次數 (Repeat Count)**：1 / 2（預設）/ 3 次。
2. **廣播速度 (Speech Rate)**：0.5x ~ 1.5x（預設 1.0x）。
3. **語音範例**：「1 號場，請張三、李四、王五、趙六上場」，重複次數為 2 則連播兩遍。
4. **觸發方式**：
   * 自動模式開啟時，場地自動補位同步自動觸發廣播
   * 團主可隨時手動點擊「叫號」按鈕重播任一場地陣容
   * 「測試語音」按鈕為獨立的立即中斷播放（用於快速測試音量/語速，不影響正式廣播佇列）
5. **佇列機制**：多筆廣播依瀏覽器原生佇列依序播放，不互相打斷——修正了先前版本「每次呼叫都強制中斷播放中語音」導致的重疊/截斷問題。

### 2.6 比賽時間與歷史對戰紀錄 (Match History Log)
* **自動時間標記**：
  * **開賽時間**：人員排進球場上場時自動記錄。
  * **結束時間**：點擊「結算此場」時記錄，並自動計算總比賽時長。
* **對戰紀錄歸檔**：系統自動存檔歷次場次：【場地名稱】+【隊伍 A 人員】vs【隊伍 B 人員】+【開賽/結束時間】。此紀錄同時作為 $W_4$ 重複扣分的資料來源。
* **比分與勝負登記 (Optional)**：結算時不強制填寫，事後可於對戰紀錄區編輯，支援僅填勝負、或完整填寫比分，皆非必填。

## 3. 版面配置與響應式網頁設計 (Layout & RWD Requirements)

### 3.1 版面配置
* **左欄**：僅放球場狀態（控制列 + 場地卡片網格）。
* **右欄**：上方為預排空間；下方為球友名單，整合功能列（新增/批次匯入/全體報到/全體休息）、篩選頁籤（全部/已報到/上場中/休息中）與名單於**單一卡片**內，不再拆成兩張獨立卡片。

### 3.2 RWD
* **桌機／平板（≥ 768px）**：左右兩欄並排顯示。
* **手機（< 768px）**：不特別設計切版邏輯，採 auto layout 讓區塊自然往下堆疊。
* **觸控目標**：點擊區域 ≥ 44 × 44px，確保手機/平板可正常操作長按。

## 5. 非功能性需求 (Non-Functional Requirements)

1. **效能要求**：自動排點與預排算力需在 1 秒內完成（候選人數規模 20-30 人內；40+ 人因窮舉法時間複雜度為 O(n⁴)，瀏覽器可能出現明顯延遲，屬已知效能邊界）。
2. **廣播穩定度**：多筆廣播依序播放，不互相打斷或截斷（見 2.5.2）。
3. **資料持久化**：比賽紀錄與名單資料儲存於瀏覽器 `LocalStorage`，重新整理頁面不會丟失記錄（僅限單機瀏覽器本地儲存，非雲端同步，符合 Demo 展示需求即可；**已知限制**：不支援多裝置/多工作人員同步操作）。
